# Lenovo Support — Auth Service (FastAPI)

Full CRUD authentication with 3 roles: **admin**, **staff**, **customer**.

## Setup

```bash
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# Edit .env and set a real SECRET_KEY:
python3 -c "import secrets; print(secrets.token_hex(32))"
```

## Run

```bash
uvicorn app.main:app --reload
```

Visit `http://localhost:8000/docs` for interactive Swagger UI (auto-generated by FastAPI).
SQLite database file `auth_system.db` is created automatically on first run.

## Creating your first admin

There's no public endpoint to create an admin (by design — admins create other
admins/staff). Bootstrap the first one manually:

```bash
python3 -c "
from database import SessionLocal, Base, engine
from models import User, UserRole
from auth_utils import hash_password

Base.metadata.create_all(bind=engine)
db = SessionLocal()
admin = User(
    email='admin@example.com',
    password_hash=hash_password('ChangeMe123!'),
    full_name='System Admin',
    role=UserRole.admin,
    is_email_verified=True,
)
db.add(admin)
db.commit()
print('Admin created:', admin.email)
"
```

## Endpoint reference

### Auth (`/auth`)
| Method | Path | Access | Notes |
|---|---|---|---|
| POST | `/auth/register` | Public | Always creates a `customer` role account |
| POST | `/auth/login` | Public | Returns access + refresh token pair |
| POST | `/auth/refresh` | Public (valid refresh token) | Rotates refresh token |
| POST | `/auth/logout` | Public (valid refresh token) | Revokes the refresh token |
| POST | `/auth/forgot-password` | Public | Always returns same message (no email enumeration) |
| POST | `/auth/reset-password` | Public (valid reset token) | Revokes all existing sessions |
| GET | `/auth/me` | Authenticated | Returns caller's own profile |

### Users (`/users`)
| Method | Path | Access | Notes |
|---|---|---|---|
| POST | `/users` | Admin only | Create staff/admin accounts directly |
| GET | `/users` | Admin, Staff | List all users, filterable by `?role=` |
| GET | `/users/{id}` | Admin, Staff, or self | Customers can only view their own record |
| PATCH | `/users/{id}` | Admin, or self | Edit name/email |
| PATCH | `/users/{id}/role` | Admin only | Change a user's role |
| DELETE | `/users/{id}` | Admin only | Soft delete (`is_active=False`) + revokes sessions |

## Authenticating requests

After login, send the access token on protected routes:

```
Authorization: Bearer <access_token>
```

Access tokens expire in 15 minutes (configurable via `.env`). When one expires,
call `/auth/refresh` with the refresh token to get a new pair — no need to
log in again until the refresh token itself expires (7 days by default).

## Security notes / production checklist

- [ ] Set a strong, random `SECRET_KEY` (never commit `.env`)
- [ ] Switch `DATABASE_URL` to Postgres/MySQL for anything beyond local dev
- [ ] Put this behind HTTPS — tokens are bearer credentials
- [ ] Send real emails for verification + password reset (currently just creates
      the token — wire up an email provider e.g. SES/SendGrid)
- [ ] Add rate limiting on `/auth/login` and `/auth/forgot-password`
      (e.g. `slowapi`) to blunt brute force / enumeration attempts
- [ ] Swap `Base.metadata.create_all` for Alembic migrations once the schema
      needs to evolve in production
- [ ] Consider adding an `auth_events` audit table (login success/failure,
      password reset, role changes) — mirrors the `ticket_events` pattern
      from the support ticketing schema
